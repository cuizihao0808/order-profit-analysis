# order-profit-analysis

订单利润分析本地工具，基于 Vite + Vue 3 + Element Plus，支持按周导入订单利润表和 Listing 销售库存表、沉淀 ASIN 主数据、在浏览器中直接维护产品状态与补货信息，并导出本地仓库 PDF 清单。

## 30 秒上手

1. 运行 `npm install && npm run dev`
2. 在 `public/data/周次目录/` 放入订单利润表和 Listing销售库存表
3. 打开 `http://127.0.0.1:8000`
4. 点击“扫描并导入”
5. 点击“导入”或“全部导入”

你日常最常用的动作只有 5 个：

- 导入新周报
- 切换视图（全部 / 重点关注 / 有补货计划）和筛选
- 直接改品名 / 产品分类 / 本地仓库 / 已下单 / 补货用时 / 备注
- 看红色风险格和黄色补货行
- 按“本地仓有货”筛选后导出 PDF 清单

## 你能用它做什么

- 扫描 `public/data/周次目录/`，按周次导入双表（订单利润 + Listing销售库存）
- 将每周表格永久保存为 JSON 快照，避免历史数据丢失
- 按店铺维护 ASIN 主数据，每个店铺一个 JSON 文件
- 支持店铺、产品分类、补货状态、库存健康四个筛选，外加 ASIN / FNSKU / 品名搜索
- 支持父子 ASIN 折叠、固定列、列显隐和列排序
- 支持在表格内直接编辑品名、产品分类、本地仓库、已下单、补货用时、每周备注
- 支持行内展开详情，分“库存详情 / 8 周趋势 / 补货批次”三个 Tab
- 支持勾选多行后批量改分类、复制 ASIN、复制包装尺寸和已下单数量
- 支持“已到库”“已发出”一键流转本地仓库和已下单数量
- 支持产品分类联动：父体标记为“放弃”时，子体自动放弃并隐藏
- 自动计算 ROI、静态补货、库存健康度、重量类型；并列展示补货批次计划给出的建议补货
- 支持导出本地仓库 PDF 清单（含产品图片）
- 支持导入反馈、toast 提示、异常值高亮、需补货行首标记、商品图片预览
- “重点关注”视图：只看配置的重点 ASIN，顶部给出最新周合计与环比
- “有补货计划”视图：按店铺查看补货批次，逐个 SKU / 整批标记已发货

所有功能都在同一个页面（ASIN 工作台）里，**只看最新一周**；历史周的数据在行内“8 周趋势”里看。右上角切换三个视图。

## 快速开始

### 1. 安装并启动

```bash
npm install
npm run dev
```

默认地址：`http://127.0.0.1:8000`

### 2. 放入周报文件

把每周数据放到独立目录（示例）：

```text
public/data/36周(08-30~09-05)/
  订单利润-ASIN-2026-08-30~2026-09-05-955119418385620992.xlsx
  Listing销售库存_2026-08-07_2026-09-05.csv
```

订单利润表需为文件名包含“订单利润”的 `.xlsx` 文件；Listing 文件需以 `Listing销售库存` 开头，支持 `.xlsx` 和 `.csv`。周次目录名称通常含“`数字周`”，例如 `36周(08-30~09-05)`；系统会将其识别为 `36周`。周起止日期从订单利润文件名里的 `YYYY-MM-DD~YYYY-MM-DD` 提取。

同一目录里出现多个候选文件时，系统会自动挑选文件名最“干净”的那个，带“副本”或 `(1)` 的会被降权；以 `~$` 开头的 Excel 临时文件直接忽略。

为保护本地导入过程，单个导入文件不能超过 10 MB，首个工作表最多 50,000 行和 200 列；订单利润表及 Listing销售库存表都必须包含 `ASIN` 列。

### 3. 进入页面导入

- 点击顶部“扫描并导入”
- 先扫描 `public/data/` 目录
- 再手动点击“导入”或“全部导入”

注意：启动项目时不会自动导入表格。

已导入周的源文件若发生变化（订单文件换了、Listing 文件有增减、源文件修改时间晚于上次导入），扫描接口会标记为“建议重新导入”，但不会再次显示在“待导入”列表。若确实需要重导，请先在“已导入”列表删除该周快照，再重新扫描。

## 常见操作

### 导入新一周数据

1. 把新一周目录放到 `public/data/`
2. 启动项目
3. 点击“扫描并导入”
4. 点击“导入”或“全部导入”
5. 导入完成后，页面自动显示新导入的最新一周

如果某些 ASIN 只出现在 Listing 表、订单利润表里没有，导入结束后会弹出“归属确认”面板，需要你为这些 ASIN 逐个选择店铺，确认后才会写入对应的 `products/shop-x.json`。

### 修改产品信息

可以直接在表格里修改以下字段，失焦后会实时写入 JSON：

- 品名
- 产品分类
- 本地仓库
- 已下单
- 补货用时
- 备注（按周保存，见下）

“备注”与其他字段不同，它存放在最新一周的快照 `weeks/{weekId}.json` 的 `notes` 里，每周一份；历史周的备注在“8 周趋势”里只读展示。其余字段都存放在店铺主数据 `products/shop-x.json` 中，跨周共享。

### 展开行详情

点击行首的 ▸ 箭头（或点“建议补货”单元格直接打开补货批次），在行下方展开面板，同时只展开一行。面板有三个 Tab：

**库存详情**

- 库存健康、FNSKU、可售、入库中、不可售、预留、FBA总量
- 包装尺寸、包装类型、包装成本、外箱尺寸、最大装箱数、单品重量、重量类型
- 装箱方式（整箱 / 混装，可切换）
- 本地仓库、已下单、补货用时（可直接编辑）
- 静态补货、建议补货、产品图片

面板底部有两个按钮：

- **已到库**：把“已下单”的数量加进“本地仓库”，并把“已下单”清零
- **已发出**：把“本地仓库”清零

**8 周趋势**（第一次打开时才加载最近 8 周快照，之后缓存）

- KPI：周销量、销售额、毛利润、毛利率、广告费率、ROI、退款率，各带与上一个有数据周次的环比；告警规则与主表一致
- 周趋势图：柱为周销量，折线为毛利润
- 历史备注：最近 8 周里写过的备注
- 趋势表：周销量、销售额、毛利润、毛利率、平均售价、广告花费、广告费率、广告单占比、ROI、退款率的逐周数值

环比规则：百分比类指标（毛利率、广告费率、广告单占比、退款率）显示百分点差值 `pp`，ROI 显示差值，其余显示变化率。销量、销售额、毛利润、毛利率、平均售价、ROI 越高越好；广告花费、广告费率、广告单占比、退款率越低越好，颜色按此区分好坏。`广告单占比 = 广告销量 / 销量`。某个 ASIN 在某周没有数据时，该周显示 `—`，不参与环比。周数据按“店铺 + ASIN”匹配。

**补货批次**（没有补货计划的 ASIN 此 Tab 不可用，例如不在补货清单里的 ASIN）

- 该 SKU 在每个批次的件数，点击即标记已发货（变绿带 ✓），再点撤销；鼠标悬停可看批次日期和标记时间
- 春节前合计、节后首班参考、采购金额、净重、生成时可用 / 在途、日均需求、残余缺口、应急判断、判断说明、备注
- 补货计划里的库存一律按清单生成那一刻的数据（CSV 的“当前可用”“在途”，截至文件修改日期），不和主数据的实时库存对齐；实时库存看“库存详情” Tab

### 批量操作

勾选表格左侧的复选框后，页面底部会浮出批量操作条（不勾选时不显示）：

- **改分类**：选一个分类，确认后把选中的所有 ASIN 改为该分类
- **复制 ASIN**：复制选中的 ASIN，每行一个
- **复制飞机盒包装信息**：只处理勾选中包装类型为“飞机盒”的 ASIN，其他包装类型自动跳过；把包装尺寸、已下单数量、包装成本（CNY）复制到剪贴板，首行为表头“包装尺寸 / 包装数量 / 包装价格”。粘贴进 Word、Excel 等支持富文本的软件会显示为带边框的表格；粘贴进只认纯文本的聊天框会得到全角字符对齐的文字表格，每列长度一致
- **✕**：取消所有选择

另有一个不依赖勾选的操作，在右上角“⋯ 更多”菜单里：**复制非放弃 ASIN**，复制当前筛选结果里所有非“放弃”的 ASIN。“更多”菜单里还有店铺管理、ASIN 主数据、字段设置和导出本地仓库 PDF。

### 导出本地仓库 PDF

入口在“⋯ 更多”菜单。有两个前置条件，任一不满足时菜单项禁用并显示原因：

1. 店铺筛选选中了单个店铺，不能是“全部”
2. 补货筛选切换到“本地仓有货”

导出的 A4 表格包含：产品图片（多图）、品名、FNSKU、本地仓库、包装尺寸、单品重量、重量类型、包装类型、备注。文件名格式为 `{周次}-{店铺导出名}-本地仓库.pdf`，店铺导出名取 `shops.json` 里的 `mdExportName`。

### 标记不再经营的产品

把产品分类改为“放弃”后：

- 当前产品会从主表格隐藏
- 如果改的是父 ASIN，则同店铺下的子 ASIN 会一起改为“放弃”
- 数据仍保存在 JSON 中，可后续恢复

### 查看哪些产品需要补货

主表并列两种补货数：

- **静态补货**：按最新一周销量和 FBA 总量的公式计算（见“计算规则”），有具体数值时显示琥珀色标签，行首有琥珀色竖线
- **建议补货**：取补货批次计划 CSV，显示“最近一个未发货批次的件数 · 批次日期”，悬停可看下一批日期和春节前合计；全部发完显示“已发完”，计划里件数全为 0 显示“计划不补”，没有计划显示 `—`
- **批次进度**：已发件数 / 计划件数

两者口径不同，可能不一致，以建议补货为发货依据。

- 补货筛选（基于静态补货）提供 6 个选项：全部 / 需要补货 / 需补货未下单 / 不需要补货 / 已下单 / 本地仓有货
- `补货用时`、`本地仓库`、`已下单` 可直接改，静态补货按 `FBA总量` 自动重算

### 查看风险产品

以下情况数值显示为红字浅红底：

- 广告费率 > 15
- 退款率 > 10
- 退货率 > 10
- 毛利润 < 0
- ROI < 0

### 重点关注视图

右上角切换到“重点关注”。主表只保留 `src/data/focusProducts.json` 里配置的 ASIN（“全部”视图里这些 ASIN 前面带 ★），按配置顺序排列；店铺、分类等筛选照常生效。

1. 在 `src/data/focusProducts.json` 里按店铺 ID 配置要跟踪的 ASIN（格式见“数据结构”），保存后页面自动热更新
2. 表格上方的“重点产品汇总”：当前筛选下重点 ASIN 在最新一周的周销量、销售额、毛利润、广告花费合计，及与上一周的环比
3. 点“一键导出ASIN”，把当前筛选下的重点 ASIN 复制到剪贴板，每行一个，顺序与表格一致
4. 逐个 ASIN 的趋势在行内“8 周趋势” Tab 里看

分类为“放弃”的重点 ASIN 与主表一样不展示。

### 有补货计划视图

右上角切换到“有补货计划”。数据来自 `src/data/replenishment/` 下的“补货清单_周批次版”CSV，每个店铺一个文件；与主表按“店铺 + ASIN”关联（CSV 里的 SKU 与周报 SKU 命名不同，不用 SKU 关联）。

1. 表格上方“补货店铺”按钮切换店铺（批次按店铺划分，此视图下店铺下拉隐藏），按钮上的数字是该店铺清单里的 SKU 数
2. **汇总**：春节前计划件数、已发货件数与完成度、下一批（日期、还剩几天、待发件数）、采购金额、净重、节后首班参考；可点“收起汇总”给表格腾空间
3. **发货批次**：每周一张卡片，显示件数、SKU 数、采购金额、净重和发货进度；状态有 待发货 / 已发 x/y / 已发货 / 逾期（批次日期已过但没发完）
4. **点一张批次卡片**选中该批次，出现操作栏：
   - **整批标记已发货** / **撤销本批已发货**
   - **复制本批清单**：把该批次的 SKU / 品名 / ASIN / 件数复制到剪贴板（Tab 分隔，可直接粘贴到 Excel），末行是合计
5. “显示”筛选：全部SKU / 有待发 / 已发完 / 仅所选批次
6. 首批在 14 天内（含逾期）的 SKU 置顶，按首批日期排序；单个 SKU 的批次在行内“补货批次” Tab 里标记

**更新清单**：把新版 CSV 放进 `src/data/replenishment/`（替换旧文件或直接放入），刷新页面。同一店铺有多个 CSV 时只用修改时间最新的那个，页面会提示被忽略的文件。已发货标记按“店铺 + ASIN + 批次完整日期（YYYY-MM-DD）”保存：新版清单里 SKU 改名不影响，只要 ASIN 和批次日期不变，标记就会保留。清单里有 SKU 缺 ASIN、或两个 SKU 共用一个 ASIN 时，页面会提示。

## 技术栈

- Vite 6
- Vue 3（`<script setup>` 单文件组件）
- Element Plus + `@element-plus/icons-vue`，通过 `unplugin-auto-import` 和 `unplugin-vue-components` 按需引入
- SheetJS (`xlsx`) 解析 xlsx / csv
- PDFKit 生成本地仓库 PDF
- 本地 JSON 文件存储
- 自定义 Vite 中间件 API
- Vitest + `@vue/test-utils` + jsdom

## 环境要求

- Node.js 18+
- npm

其他命令：

```bash
npm run build
npm test
npm run test:coverage
npm run cleanup:dup-asin
```

`npm run preview` 仅预览前端构建产物，不包含本项目的本地文件 API；需要导入、编辑或导出数据时，请使用 `npm run dev`。

`npm run cleanup:dup-asin` 用于合并跨店铺重复的 ASIN 记录，脚本在 `scripts/cleanup-duplicate-asins.mjs`。

每次导入周数据或删除周快照前，应用会自动将 `src/data/` 备份到 `.opa-backups/`，并仅保留最近 10 份。恢复时请先停止开发服务器，再用对应备份目录中的 `data/` 替换 `src/data/`。备份与测试覆盖率报告均不会提交到 Git。

开发模式下每次重启 dev server 都会生成新的会话 ID，前端发现 ID 变化时会清空所有 `opa:` 开头的 localStorage，避免旧列配置和旧筛选残留。

## 测试与构建

```bash
# 全部单元、集成和界面测试
npm test

# 跑全部测试并生成覆盖率报告（CI 用这个）
npm run test:coverage

# 仅运行本地 API 集成测试
npm run test:api

# 仅运行界面测试（*.ui.test.js：页面冒烟、组件、导入弹窗）

```

测试分四层：

| 层 | 文件 | 内容 |
|----|------|------|
| 业务规则 | `tests/{dataPipeline,restockRules,productUpdates,importScan,weekSnapshot,trendMetrics,replenishmentPlan,tableView}.test.js` | `src/lib/` 的纯函数 |
| composables | `tests/composables.test.js` | 补货计划加载 / 已发货标记、8 周快照按需加载，fetch 用模拟数据 |
| 组件 | `tests/components.ui.test.js`、`tests/importDialog.ui.test.js` | 用真实 Element Plus 挂载单个组件 |
| 页面 | `tests/app.ui.test.js`、`tests/app.actions.ui.test.js` | 挂载整页，接口用 `tests/helpers/appHarness.js` 里有状态的模拟 API（写操作会改内存数据并记录请求）。覆盖视图切换、搜索、展开行三个 Tab、内联编辑与失败回滚、批量改分类、复制包装表格、更多菜单（导出 PDF、列设置）、店铺 / ASIN 增删改、导入与归属确认、删除周次、图片预览、整批标记发货 |
| 本地 API | `tests/importApi.integration.test.js` | 起一个真实 Vite 中间件，在临时目录里读写 JSON / CSV；包括 PDF 导出（只抓公网 https 图片、超 5MB 拒绝、失败占位、多页）和删除 / 导入前的自动备份（只留最新 10 份） |

覆盖率统计整个 `src/`（不含 `main.js` 和 `src/data/`），按目录设门槛，低于门槛会失败：

| 范围 | 行 / 语句 | 函数 | 分支 |
|------|-----------|------|------|
| `src/lib/**` | 95% | 95% | 90% |
| `src/composables/**` | 95% | 95% | 85% |
| `src/components/**` | 90% | 60% | 80% |
| 整体（含 `App.vue`） | 90% | 80% | 80% |

`vite.config.js` 里的本地 API 由集成测试覆盖，但不计入覆盖率（Vite 会先打包配置文件再执行，覆盖率工具对不上源码行号）。

测试文件并行跑，每个文件一个独立进程，全部测试约 5 秒。测试里的“今天”都用假时钟固定，CSV 的修改时间也固定，结果不随运行日期变化。

仓库中的 CI 会在推送和 Pull Request 时运行 `npm run test:coverage`（包含全部测试）和生产构建。

## 数据结构

```text
src/data/
  shops.json                店铺列表
  weeks.json                周快照索引
  restockConfig.js          补货计算参数
  focusProducts.json        重点关注产品的 ASIN 清单
  replenishment/
    *.csv                   补货清单_周批次版，每个店铺一个
    shipped.json            补货批次的已发货标记（首次标记时自动创建）
  products/
    shop-1.json             店铺 1 的 ASIN 主数据
    shop-2.json             店铺 2 的 ASIN 主数据
    shop-3.json             店铺 3 的 ASIN 主数据
  weeks/
    {weekId}.json           单周快照
```

### shops.json

保存店铺主数据，例如：

```json
[
  {
    "id": "shop-1",
    "name": "CZH-主店一号",
    "mdExportName": "一号店",
    "country": "美国",
    "note": ""
  }
```

**手工维护，导入时不会被覆盖：**

| 字段 | 说明 |
|------|------|
| `name` | 品名 |
| `category` | 产品分类 |
| `restockCycle` | 补货用时，默认 2 |

### weeks/{weekId}.json

保存单周快照：

- `id`: 周次 ID
- `filename`: 订单利润源文件相对路径
- `listingFiles`: 该周使用的 Listing 文件名列表
- `columns`: 订单利润表原始表头
- `rows`: 原始行数据，形如 `{ asin, values }`，`values` 与 `columns` 一一对应
- `notes`: 该周的 ASIN 备注，形如 `{ "B0XXXX": "备注内容" }`

这部分用于保留每周指标，不会因为后续编辑主数据而丢失历史值。

### focusProducts.json

“重点关注”视图的配置，键为店铺 ID，值为 ASIN 数组，数组顺序就是该视图里的排序：

```json
{
  "shop-1": ["B0D3HJPD2P", "B0CYCGY6NM"],
  "shop-2": ["B0HCZT8BMB"],
  "shop-3": []
}
```

这个文件只能手工编辑，页面上没有增删入口，也没有对应的 API。它由前端直接 `import`，不经过 `/api`。

### replenishment/*.csv

“有补货计划”视图的数据源，UTF-8（可带 BOM）的 CSV，每个文件对应一个店铺（取“店铺”列的值，如 `TZH`）。按表头识别：

| 表头 | 说明 |
|------|------|
| `店铺` `SKU` | 必填；没有 SKU 列或没有批次列的文件会被跳过并提示 |
| `品名` `ASIN` `当前可用` `在途` `判断说明` `春节前合计` | 同名列 |
| `日均需求…` `…应急…` `…残余缺口` `…节后首班…` `…采购金额…` `…净重…` `备注…` | 按关键字匹配，表头里的日期等文字变化不影响识别 |
| `MM/DD` 或 `MM/DD(说明)` | 每周批次列，值为该 SKU 在该批次的发货件数；括号里的说明（如“仅现货”“春节前末班”）显示在批次卡片上 |

- SKU 以“每周”开头的行是每周合计，按名称识别件数、采购金额、净重、SKU 数，其中采购金额和净重用于批次卡片
- 批次表头只有月/日，年份以文件修改时间为准，月份回退时（12 月 → 1 月）自动跨年
- 店铺简称会按前缀匹配 `shops.json` 的店铺名（`TZH` → `TZH-主店二号`）用于显示；产品图片按 ASIN 从店铺主数据里取

CSV 自己解析，不经过 SheetJS，因为 SheetJS 会把 `10/10` 这类表头当成日期改写。

### replenishment/shipped.json

补货批次的已发货标记，按“店铺简码 → ASIN → 批次完整日期”保存，值为标记时间：

```json
{
  "TZH": {
    "B0H4GWDVHD": { "2026-10-17": "2026-10-14T07:34:34.217Z" }
  }
}
```

撤销后对应的键会被删除。旧版按“SKU → MM/DD”保存的标记不再生效，页面会提示重新标记。

批次的年份由 CSV 表头的“MM/DD”加文件修改时间推断（见 `inferBatchDates`）。复制或 checkout 会改变文件修改时间，跨年时可能推错年份，此时已有标记对不上日期、会显示为未发货。

## 导入规则

导入时系统会自动：

- 备份 `src/data/` 到 `.opa-backups/`
- 写入 `src/data/weeks/{weekId}.json`
- 更新 `src/data/weeks.json`
- 发现新店铺时自动追加到 `shops.json`
- 发现新 ASIN 时，按店铺写入对应的 `products/shop-x.json`
- 用 Listing 表刷新库存、包装、图片等字段

已存在的 ASIN：

- 不覆盖已维护的品名、分类、补货用时、本地仓库、已下单、装箱方式
- 更新 `lastSeenWeek` 和 Listing 来源字段

只在 Listing 表里出现、订单利润表里没有的 ASIN，无法自动判断店铺归属，会进入导入后的归属确认面板，由你选择店铺后再写入。

### 计算规则

#### ROI

```text
毛利润 / 采购成本
```

说明：

- 不取整：表格展示两位小数，告警和环比用原值（例如 -0.004 显示为 -0.00，仍标红）

- 快照中采购成本通常为负数，计算和展示时都取绝对值
- ROI 的正负由毛利润决定
- 采购成本为 0 或缺失时返回空

#### 静态补货

```text
IF(FBA总量 < 周销量 * (restockMonths + 补货用时), 周销量 * restockMultiplier * quantityDiscount, "无需补货")
```

参数在 `src/data/restockConfig.js` 中配置，当前值为 `restockMonths: 8`、`restockMultiplier: 8`、`quantityDiscount: 1`。

说明：

- 这里的“周销量”直接取最新一周周报中的 7 天销量
- 库存不足两个月（8 周）加补货周期时，补充两个月（8 周）销量
- 周销量为 0 时直接返回“无需补货”
- FBA总量、周销量、补货用时任一缺失时返回空
- 若计算结果需要补货，该格显示琥珀色标签，行首有琥珀色竖线

#### 库存健康

```text
(可售 + 预留) > 月销量 * 1.5 ? "健康" : "不足"
```

#### 重量类型

```text
体积重(g) = 长 * 宽 * 高 / 6000 * 1000
单品重量 > 体积重 ? "实重" : "抛重"
```

包装尺寸解析不出三个维度，或单品重量缺失时显示 `—`。

### 产品分类

支持五种状态：

- 正常
- 新品
- 观望
- 断货
- 放弃

规则：

- 父体改为“放弃”时，同店铺下的所有子体自动改为“放弃”
- “放弃”的产品不会在主表格中展示，但仍保留在 JSON 中

- 含整箱产品的父组排在前面，其余按毛利润从高到低
- 组内先按毛利润从高到低，再把整箱产品提到前面
- “重点关注”视图按 `focusProducts.json` 的顺序；“有补货计划”视图把首批在 14 天内的 SKU 按首批日期置顶

## 问题排查

### 为什么没看到待导入文件

常见原因：

- 文件不在 `public/data/周次目录/` 下
- 订单利润文件名不含“订单利润”，或后缀不是 `.xlsx`
- Listing 文件名不以 `Listing销售库存` 开头
- 文件名以 `~$` 开头（Excel 临时文件会被自动忽略）
- 该文件已经导入过（会显示在“已导入”，不会出现在“待导入”）

建议按下面顺序检查：

1. 确认文件路径是 `public/data/xxx周xxx/订单利润xxx.xlsx`
2. 回到页面点击“扫描并导入”重新扫描
3. 在导入抽屉里看“已导入”列表里是否已存在同名周次
4. 如果想重导，先删除该周快照，再重新扫描导入

### 为什么启动后没自动导入

这是当前设计，不是故障：

- 启动时只加载已有 JSON（店铺、产品、周索引）
- 不会自动扫描并导入表格
- 必须手动点击“扫描并导入”再执行导入

这样可以避免每次启动都改动本地数据文件。

### 为什么放弃产品看不到了

这是当前规则：

- 产品分类为“放弃”后，不在主表格展示
- 如果父 ASIN 标记为“放弃”，同店铺的子 ASIN 也会联动“放弃”并隐藏

如果要恢复展示：

1. 打开“ASIN”管理抽屉
2. 搜索该 ASIN
3. 把分类从“放弃”改回“正常 / 观望 / 断货”

如果在主表里找不到它，这是正常现象，需要在 ASIN 抽屉中恢复。

### 为什么导出 PDF 按钮点不动

按钮需要同时满足两个条件：选中单个店铺，并且补货筛选切换到“本地仓有货”。鼠标移到按钮上会提示当前缺哪个条件。筛选结果为空时同样无法导出。

### 为什么导出的 PDF 里中文变成方块

PDF 生成依赖系统中文字体，按以下顺序查找，用第一个存在的：

- macOS：Arial Unicode、STHeiti Medium、PingFang
- Windows（`%WINDIR%\Fonts`）：微软雅黑 `msyh.ttc`、黑体 `simhei.ttf`、宋体 `simsun.ttc`

都找不到时（例如 Linux）中文会退化为默认字体而变成方块。需要支持其他字体时，在 `vite.config.js` 的 `choosePdfFont` 里追加候选；`.ttc` 字体集合必须同时填写 `family`（字体的 PostScript 名），否则 PDFKit 无法加载。

### 为什么导出的 PDF 里缺图片

图片是服务端现拉取的，以下情况会跳过：

- 不是 https 链接
- 指向 localhost 或内网地址
- 单张超过 5 MB
- 拉取超时或失败

每行最多渲染 12 张图片。

## 开发说明

- 入口 `src/main.js` 直接挂载 `src/App.vue`（ASIN 工作台，单页）
- 展开行的两个 Tab 是独立组件：`src/components/TrendPanel.vue`（8 周趋势，手写 SVG，没有引入图表库）、`src/components/PlanDetail.vue`（补货批次）
- “有补货计划”视图顶部的汇总与批次条在 `src/components/PlanOverview.vue`
- 第二行的筛选胶囊是 `src/components/FilterChip.vue`
- 样式在 `src/style.css`，末尾“方案 A”一节是当前的视觉规范（黑白极简，颜色只用于红 / 琥珀 / 绿三种状态），覆盖前面的旧规则
- 补货计划加载 / 已发货标记、最近 8 周快照的按需加载与缓存分别在 `src/composables/useReplenishment.js`、`src/composables/useTrendWeeks.js`
- 导入弹窗在 `src/components/ImportDialog.vue`
- 剪贴板写入在 `src/utils/clipboard.js`
- 导入、JSON 读写、PDF 生成、API 中间件都在 `vite.config.js`
- 可测试的业务规则抽在 `src/lib/` 下：
  - `restockRules.js` 静态补货公式
  - `productUpdates.js` 分类联动与整箱优先排序
  - `dataPipeline.js` 表格解析、字段归一化、文件名识别
  - `importScan.js` 扫描结果过滤
  - `weekSnapshot.js` 周快照读数、ROI、告警规则、库存健康、重量类型
  - `trendMetrics.js` 趋势指标、环比、趋势图坐标
  - `replenishmentPlan.js` 补货清单 CSV 解析、批次日期推断、发货进度汇总、已发货标记、按店铺 + ASIN 关联、建议补货
  - `tableView.js` 主表的列配置合并与排序、补货筛选、父 ASIN 分组排序、表头分组、建议补货 / 批次进度展示、剪贴板表格

新增业务规则时优先放进 `src/lib/` 写成纯函数，`App.vue` 只负责取值和渲染，这样规则才能被单元测试直接覆盖。

## 备注

这是一个本地使用工具，数据直接写入仓库内的 JSON 文件。

本地 API 仅监听 `127.0.0.1`。店铺 ID、周次 ID、导入文件尺寸与工作表规模都会在服务端校验；PDF 导出仅下载受限制的 HTTPS 图片资源。

如果要迁移到多人协作或线上部署，需要额外补：

- 数据库
- 用户权限
- 文件上传接口
- 并发写入保护
