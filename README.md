# order-profit-analysis

订单利润分析本地工具，基于 Vite + Vue 3，支持按周导入 xlsx、沉淀 ASIN 主数据、在浏览器中直接维护产品状态与补货信息。

## 30 秒上手

1. 运行 `npm install && npm run dev`
2. 在 `public/data/第x周目录/` 放入订单利润表和 Listing销售库存表
3. 打开 `http://127.0.0.1:8000`
4. 点击“扫描并导入”
5. 点击“导入”或“全部导入”

你日常最常用的动作只有 4 个：

- 导入新周报
- 切换周次和店铺
- 直接改品名 / 产品分类 / 库存数量 / 补货用时
- 看红色风险格和黄色补货行

## 你能用它做什么

- 扫描 `public/data/第x周目录/`，按周次导入双表（订单利润 + Listing销售库存）
- 将每周 xlsx 永久保存为 JSON 快照，避免历史数据丢失
- 按店铺维护 ASIN 主数据，每个店铺一个 JSON 文件
- 支持店铺筛选、父子 ASIN 折叠、固定列、列显隐和列排序
- 支持在表格内直接编辑品名、产品分类、补货用时、本地仓库、已下单
- 支持产品分类联动：父体标记为“放弃”时，子体自动放弃并隐藏
- 自动计算 ROI、补货数量
- 支持导入反馈、toast 提示、异常高亮、补货整行高亮

## 快速开始

### 1. 安装并启动

```bash
npm install
npm run dev
```

默认地址：`http://127.0.0.1:8000`

### 2. 放入周报文件

把每周数据放到独立目录（示例）：

```text
public/data/31周 (07:26～08:01)/
  订单利润-ASIN-2026-07-26~2026-08-01-942789467646570496.xlsx
  Listing销售库存_2026-07-06_2026-08-04.csv
```

订单利润表建议保持原始命名，Listing 文件需以 `Listing销售库存` 开头。

### 3. 进入页面导入

- 点击顶部“扫描并导入”
- 先扫描 `public/data/` 目录
- 再手动点击“导入”或“全部导入”

注意：启动项目时不会自动导入 xlsx。

## 常见操作

### 导入新一周数据

1. 把新一周目录放到 `public/data/`
2. 启动项目
3. 点击“扫描并导入”
4. 点击“导入”或“全部导入”
5. 导入完成后，系统会自动切到最新周次

### 修改产品信息

可以直接在表格里修改以下字段，失焦后会实时写入 JSON：

- 品名
- 产品分类
- 本地仓库
- 已下单
- 补货用时

### 标记不再经营的产品

把产品分类改为“放弃”后：

- 当前产品会从主表格隐藏
- 如果改的是父 ASIN，则子 ASIN 会一起改为“放弃”
- 数据仍保存在 JSON 中，可后续恢复

### 查看哪些产品需要补货

- 补货数量有具体数值时，整行黄色高亮
- `补货用时`、`本地仓库`、`已下单` 可直接改，补货数量按 `FBA总量` 自动重算

### 查看风险产品

以下情况会整格标红：

- 广告费率 > 15
- 退款率 > 10
- 退货率 > 10
- 毛利润 < 0
- ROI < 0

## 数据结构

```text
src/data/
  shops.json                店铺列表
  weeks.json                周快照索引
  products/
    shop-1.json             店铺 1 的 ASIN 主数据
    shop-2.json             店铺 2 的 ASIN 主数据
    shop-3.json             店铺 3 的 ASIN 主数据
  weeks/
    {weekId}.json           单周 xlsx 快照
```

### shops.json

保存店铺主数据，例如：

```json
[
  {
    "id": "shop-1",
    "name": "CZH-主店一号",
    "country": "美国",
    "note": ""
  }
]
```

### products/shop-x.json

每个店铺一个文件，保存该店铺下的 ASIN 主数据。当前字段包括：

- `asin`
- `parentAsin`
- `name`
- `category`
- `restockCycle`
- `stock`
- `firstSeenWeek`
- `lastSeenWeek`

示例：

```json
[
  {
    "asin": "B0D3HJPD2P",
    "parentAsin": "B0DP46YRCG",
    "name": "梅森罐盖无日期24Wide+24Regular",
    "category": "正常",
    "restockCycle": 2,
    "stock": "",
    "firstSeenWeek": "订单利润-ASIN-2026-07-12~2026-07-18-937769247582007296",
    "lastSeenWeek": "订单利润-ASIN-2026-07-12~2026-07-18-937769247582007296"
  }
]
```

### weeks/{weekId}.json

保存单周快照：

- `columns`: 原始表头
- `rows`: 原始行数据，按 ASIN 关联

这部分用于保留每周指标，不会因为后续编辑主数据而丢失历史值。

系统会从文件名中提取周起止日期。

## 导入规则

导入 xlsx 时系统会自动：

- 写入 `src/data/weeks/{weekId}.json`
- 更新 `src/data/weeks.json`
- 发现新店铺时自动追加到 `shops.json`
- 发现新 ASIN 时，按店铺写入对应的 `products/shop-x.json`

已存在的 ASIN：

- 不覆盖已维护的品名、分类、库存、补货用时
- 只更新 `lastSeenWeek`

## 页面规则

### 字段与规则速查

| 字段 | 来源 | 是否可编辑 | 规则 / 说明 |
|------|------|------------|-------------|
| 品名 | `products/shop-x.json` | 是 | 直接在表格中修改，实时写回 JSON |
| ASIN | xlsx + products 主键 | 否 | 用于关联快照和主数据 |
| 产品分类 | `products/shop-x.json` | 是 | 可选：正常 / 观望 / 断货 / 放弃 |
| 销量 | 周快照 | 否 | 这里按周报里的 7 天销量使用 |
| 采购成本 | 周快照 | 否 | xlsx 原始通常为负数，展示时转为正数 |
| 毛利润 | 周快照 | 否 | 小于 0 整格标红 |
| 广告费率 | 周快照 | 否 | 大于 15 整格标红 |
| 退款率 | 周快照 | 否 | 大于 10 整格标红 |
| 退货率 | 周快照 | 否 | 大于 10 整格标红 |
| ROI | 公式 | 否 | `ROUND(毛利润 / 采购成本, 2)` |
| 库存数量 | `products/shop-x.json` | 是 | 修改后会影响补货数量计算 |
| 补货用时 | `products/shop-x.json` | 是 | 默认 2，修改后会影响补货数量计算 |
| 补货数量 | 公式 | 否 | 有具体数值时整行高亮 |

### 固定列

- 品名
- ASIN

### 默认展示列顺序

- 品名
- ASIN
- 产品分类
- 销量
- 采购成本
- 毛利润
- 广告费率
- ROI
- 库存数量
- 补货用时
- 补货数量

其余列默认隐藏，但可在“字段”面板中自行控制。

### 计算规则

#### ROI

```text
ROUND(毛利润 / 采购成本, 2)
```

说明：

- xlsx 中采购成本通常为负数，展示时按正数显示
- ROI 的正负由毛利润决定

#### 补货数量

```text
IF(库存数量 < 销量 * (12 + 补货用时), 销量 * 4 * 0.8, "无需补货")
```

说明：

- 这里的“销量”直接取周报中的 7 天销量
- 若计算结果需要补货，则整行高亮

### 产品分类

支持四种状态：

- 正常
- 观望
- 断货
- 放弃

规则：

- 父体改为“放弃”时，所有子体自动改为“放弃”
- “放弃”的产品不会在主表格中展示，但仍保留在 JSON 中

### 排序规则

- 父组按毛利润从高到低排序
- 组内子 ASIN 也按毛利润从高到低排序

## 高亮规则

### 红色整格

- 广告费率 > 15
- 退款率 > 10
- 退货率 > 10
- 毛利润 < 0
- ROI < 0

### 黄色提示

- 补货数量有具体数值时，整行高亮

## 问题排查

### 为什么没看到待导入文件

常见原因：

- 文件不在 `public/data/` 目录
- 文件后缀不是 `.xlsx`
- 文件名以 `~$` 开头（Excel 临时文件会被自动忽略）
- 该文件已经导入过（会显示在“已导入”，不会出现在“待导入”）

建议按下面顺序检查：

1. 确认文件路径是 `public/data/xxx.xlsx`
2. 回到页面点击“扫描并导入”重新扫描
3. 在导入抽屉里看“已导入”列表里是否已存在同名周次
4. 如果想重导，先删除该周快照，再重新扫描导入

### 为什么启动后没自动导入

这是当前设计，不是故障：

- 启动时只加载已有 JSON（店铺、产品、周索引）
- 不会自动扫描并导入 xlsx
- 必须手动点击“扫描并导入”再执行导入

这样可以避免每次启动都改动本地数据文件。

### 为什么放弃产品看不到了

这是当前规则：

- 产品分类为“放弃”后，不在主表格展示
- 如果父 ASIN 标记为“放弃”，子 ASIN 也会联动“放弃”并隐藏

如果要恢复展示：

1. 打开“ASIN”管理抽屉
2. 搜索该 ASIN
3. 把分类从“放弃”改回“正常 / 观望 / 断货”

如果在主表里找不到它，这是正常现象，需要在 ASIN 抽屉中恢复。

- `GET /api/shops`

- `POST /api/products`
- `PUT /api/products/:asin`
- `DELETE /api/products/:asin`
- `GET /api/weeks`
- `GET /api/weeks/:id`
- `DELETE /api/weeks/:id`
- `GET /api/scan`
- `POST /api/import`
